# 神力干预系统

> 文档状态：v1.1（2026-07-14 前端重构同步）
> 前次版本：v1.0（2026-06-12）
> 所属阶段：P0
> 用途：定义玩家如何用神力影响事件、NPC 和命运走向

## 更新说明（v1.1）

本轮把「托梦」和「赐福」两个 MVP 干预从「事件面板一次性下拉列表」拆成两种入口不同的独立体验：

- **托梦**：入口从事件面板迁至**人物面板**（角色框内），只在**夜晚**可用，**每日 1 次**，消耗改为 **3 神力**，作用改为「向该 NPC 写入一条记忆」，不直接改属性 / 情绪 / 资源；由 NPC 在后续行为中自行读取解释。
- **赐福**：入口从事件面板迁至**事件推进面板的关键节点**（VN 对话段），一场事件可有**多个可赐福节点**，每个节点独立显示「目的 / 难度值 / 消耗 / 成功文案 / 失败文案」，命中或错过都作数即时演出。
- 其余四类干预（牵引机缘 / 遮蔽灾兆 / 显灵警示 / 强化观察）本次未落地实现，暂保留策划占位（详见 §5）。

---

## 1. 系统目标

神力干预系统是玩家与小镇命运互动的核心。玩家不是直接控制 NPC，而是以土地公身份在关键节点进行间接影响。

系统目标：

1. 让玩家能做出有代价的选择。
2. 让干预结果影响事件、NPC 状态、资源和结局。
3. 保持“不能直接操控人类意志”的世界观限制。
4. 支持正神、邪神、中性等不同路线。

---

## 2. 干预原则

### 2.1 玩家不能做什么

玩家不能：

- 直接命令 NPC 行动。
- 直接修改已发生事件。
- 直接杀死或复活 NPC。
- 直接改变 NPC 核心人格。
- 无代价地获得完整真相。

### 2.2 玩家可以做什么

玩家可以：

- 让 NPC 做梦。
- 给某次行动带来好运。
- 让两个人更容易相遇。
- 暂时遮蔽某条信息。
- 用显灵制造警示。
- 强化自己对命运线的观察。

## 4. 玩家可见信息

干预按钮应显示：

- 干预名称
- 神力消耗
- 目标对象或事件
- 大致结果倾向
- 是否有风险
- 是否当前可用

示例：

```text
托梦（消耗 2 神力）
让林潮音梦见危险征兆，可能提高她对寺庙异常的警觉。
```

成功率不显示精确数值，只显示：

```text
容易 / 普通 / 困难 / 几乎不可能
```

## 5. 干预详规

### 5.1 托梦（v1.1）

| 项目 | 规则 |
|---|---|
| 目标 | 单个 NPC |
| 入口 | 人物面板右上角「托梦」按钮 |
| 时段限制 | **仅夜晚可用** |
| 频次限制 | **玩家每日只能托梦 1 次**（跨 NPC 共用配额） |
| 消耗 | **3 神力** |
| 输入形式 | 弹出文本框，玩家写一段自然语言梦境提示（也可选预设） |
| 作用 | 向目标 NPC 写入一条「土地公托梦」类型的记忆条目 |
| 数值影响 | **不直接改**属性 / 情绪 / 资源 / 缘线 / 业线 |
| 作用途径 | 由 NPC 在后续 think / 事件对话中读取该记忆并自行解释、影响其行为倾向 |
| 表现反馈 | 关闭对话框后 Toast「梦境已投递」；人物面板托梦按钮转为「今夜已托梦」灰态 |
| 失败态 | 不存在"失败"：只要付出神力就一定写入记忆；后果由 NPC 后续行为体现 |

适用场景：

- 提醒林潮音注意异常。
- 让陈远舟重新思考离岛计划。
- 让苏婉察觉陈海生危险状态。

设计意图：把「托梦」从一个可算成功率的干预按钮，改成一个**低频、高沉浸、需要玩家写文本、结果不可预测**的仪式性操作，让神力真正体现为"只能影响意念，不能影响行为"。

### 5.2 赐福（v1.1）

| 项目 | 规则 |
|---|---|
| 目标 | 一场事件推进中的**某个关键节点** |
| 入口 | 事件推进面板的 VN 段落间，遇到 `blessing_prompt` 段时暂停并弹出决策弹窗 |
| 节点数 | **一场事件可以有多个赐福节点**（示例：`w1_haisheng_port_night` 有 2 个） |
| 消耗 | 由节点独立定义，默认 3 神力；不同节点可不同 |
| 每节点次数 | **每个节点独立决策一次**（赐 / 不赐）；玩家跳过不算消耗 |
| 决策弹窗必含字段 | 目的 / 难度文本 / 难度值 / 消耗 / 成功文案 / 失败文案 |
| 判定 | 使用命运硬币（§7）：抛 N 枚硬币，正面数 ≥ 节点难度值 = 成功；赐福时 N +1 |
| 表现反馈 | 决策后立即回到事件叙事流，播放"成功文案"或"失败文案"对应段落 |
| 资源倾向 | 阳德 |

字段示例（内容层）：

```text
blessing_prompt:
  purpose:          让海生把这一夜留给家
  difficulty_text: 临门一脚 · 需求 2 面
  difficulty_value: 2
  cost:             3
  success_effect:  海生忽然想起远舟前夜说过的一句话，转身朝家走。
  failure_effect:  神力被夜风吹散，海生把船票稳稳收进内袋。
```

设计意图：把「赐福」从事件开始前的一次性下拉，改成**演出过程中的关键抉择**。玩家能读到具体戏剧张力时才决定要不要花神力，选择因此更"有感"；一场事件多个节点意味着玩家要在同一事件里分配神力。

### 5.3 牵引机缘（未实现 · P1）

| 项目 | 规则 |
|---|---|
| 目标 | 两名 NPC / NPC 与地点 |
| 消耗 | 4 神力 |
| 作用 | 提高相遇、发现、对话或事件触发概率 |
| 典型效果 | 让两人同一时段到同一地点 |
| 资源倾向 | 中性或阳德 |
| 风险 | 也可能让错误的人相遇 |

适用场景：

- 让许明川遇到周行知。
- 让林潮音避开顾沉舟。
- 让苏婉提前发现家庭风险。

### 5.4 遮蔽灾兆

| 项目 | 规则 |
|---|---|
| 目标 | 信息 / 线索 / 风险提示 |
| 消耗 | 3 神力 |
| 作用 | 暂时降低 NPC 或系统对某风险的察觉 |
| 典型效果 | 延迟调查、隐藏证据、避免短期冲突 |
| 资源倾向 | 阴德 |
| 风险 | 长期可能导致更大事故 |

适用场景：

- 暂时阻止许明川发现某条证据。
- 避免寺庙腐败立刻暴露。
- 让邪教线继续推进以换取其他路线收益。

### 5.5 显灵警示

| 项目 | 规则 |
|---|---|
| 目标 | 地点 / 群体 / 关键事件 |
| 消耗 | 5 神力 |
| 作用 | 强制制造明显警告，影响多个 NPC |
| 典型效果 | 降低高风险事件发生概率，提升香火或恐惧 |
| 资源倾向 | 阳德，但可能造成恐慌 |
| 风险 | 过度使用可能让居民畏惧而非信任 |

适用场景：

- 寺庙火灾前警示。
- 港口夜船前警示。
- 庙会聚集前警示。

### 5.6 强化观察

| 项目 | 规则 |
|---|---|
| 目标 | NPC / 事件 / 地点 |
| 消耗 | 1 神力 |
| 作用 | 显示更多风险或可能影响 |
| 典型效果 | 解锁一条模糊提示 |
| 资源倾向 | 中性 |
| 风险 | 不直接改变事件结果 |

## 6. 干预窗口

不是所有时候都能干预。事件可配置干预窗口。

| 窗口 | 说明 | 示例 |
|---|---|---|
| 事件前 | 事件还未发生，只能影响触发概率或参与者状态 | 让陈远舟更有勇气 |
| 事件中 | 事件正在推进，可改变分支 | 争吵中托梦提醒 |
| 事件后 | 事件已发生，只能影响后续补救 | 事故后引导和解 |

P0 阶段建议优先支持：

```text
事件前干预
事件中一次选择干预
```

## 7. 成功判定

### 7.1 MVP 简化判定

P0 可使用固定修正：

```text
最终判定值 = 事件基础值 + NPC 状态修正 + 干预修正
```

| 结果 | 判定 |
|---|---|
| 成功 | 最终判定值 ≥ 目标难度 |
| 部分成功 | 最终判定值接近目标难度 |
| 失败 | 最终判定值 < 目标难度 |

### 7.2 命运硬币表现

UI 可把判定包装成命运硬币：

```text
硬币数 = 基础硬币 + 角色状态硬币 + 干预奖励硬币
需求值 = 事件难度
```

玩家看到的是硬币和结果，不需要看到底层公式。

## 8. 结果影响

干预可能影响：

| 目标 | 示例 |
|---|---|
| 资源 | 神力 -3、阳德 +5、阴德 +3、香火 +2 |
| NPC 状态 | 警觉 +1、压力 -1、信任 +1 |
| 事件结果 | 成功 / 部分成功 / 失败 |
| 事件触发 | 后续事件解锁或阻断 |
| 关系 | 缘线强度改变 |
| 业线 | 业线节点推进或偏移 |
| 结局 | 路线倾向变化 |

---

## 9. 与资源系统的关系

- 所有干预都必须先检查神力。
- 干预消耗立即扣除，除非设计明确允许失败不扣。
- 阳德 / 阴德变化在事件结算后统一处理。
- 不允许 UI 直接修改资源，必须通过干预或事件结算。

## 13. 边界情况

| 情况 | 处理 |
|---|---|
| 神力不足 | 禁用按钮并提示 |
| 事件无干预窗口 | 不显示干预按钮 |
| 目标 NPC 不在事件中 | 只允许事件前牵引类干预 |
| 同一事件多次干预 | P0 默认只允许一次 |
| 干预失败 | 仍记录历史，并显示轻微反馈 |
| 阴德干预导致短期好结果 | 允许，但记录阴德和后续风险 |

## 15. 验收标准

- [ ] 事件推进面板遇到含 `blessing_prompt` 的段落时暂停并弹出赐福决策弹窗。
- [ ] 赐福决策弹窗展示：目的、难度文本、难度值、消耗、成功/失败文案预告。
- [ ] 一场事件的多个赐福节点各自独立结算，玩家可在同一事件内分别选择赐/不赐。
- [ ] 神力不足时赐福按钮禁用，跳过按钮仍可用。
- [ ] 赐福使命运硬币数 +1，判定按 §7 规则执行。
- [ ] 人物面板在**夜晚**且**当日未托梦**时显示可点击的「托梦」按钮，其它时段/已托梦时按钮灰化并说明原因。
- [ ] 托梦弹窗接受玩家文本输入并在确认时扣 3 神力、写入 NPC 记忆、置日内配额为已用。
- [ ] 托梦不改变属性/情绪/资源/缘线/业线；只以 NPC 后续行为体现影响。
- [ ] 干预结果（赐福节点结果、托梦条目）能写入历史记录。
- [ ] 阴德类干预（未实现）暂不出现在 UI，日后引入时挂到对应入口。
