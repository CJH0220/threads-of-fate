# UI 规格：事件推进面板

> 文档状态：v1.1（2026-07-14 前端重构同步）
> 前次版本：初稿（2026-06-10）
> 所属阶段：P0
> 引擎方向：Godot
> 美术方向：简约像素风

## 更新说明（v1.1）

- **关键节点赐福**：干预从"事件开始前一次性下拉"改为"演出中段落级弹窗"，同一事件可有多个赐福节点，各自独立决策与结算（§14）。
- **事件锁定与回看**：事件演出结束后**永久锁定**并写入 `CompletedSnapshot`，事件列表以「✓ 已完成」显示，再次进入切换为回看模式，不弹赐福弹窗、不消耗神力（§15）。

## 1. 用途

事件推进面板用于呈现关键事件的叙事文本、参与角色、玩家干预、事件结果和结算反馈。它是“观察 → 干预 → 结果反馈”核心循环中最重要的反馈界面。

---

## 2. 入口与出口

### 入口

| 来源 | 触发 |
|---|---|
| 主地图 | 点击事件标记 |
| 地点面板 | 点击地点事件 |
| 推动时间 | 时间推进后自动触发关键事件 |
| 人物面板 | 点击人物相关事件 |

### 出口

| 操作 | 结果 |
|---|---|
| 事件未结束时点击继续 | 推进下一段文本 |
| 结算阶段点击确定 | 按后续跳转规则进入下一界面 |
| Esc | 非关键事件可退出；关键事件需确认 |

---

## 3. 布局规格

```text
┌──────────────────────────────────────────────┐
│ 事件名：港口的夜色                  [Auto]   │
├───────────────┬──────────────────────────────┤
│ 参与角色       │ 事件文本区                    │
│ 林潮音 头像     │ “她站在港口边，像是在等待……” │
│ 陈远舟 头像     │                              │
├───────────────┴──────────────────────────────┤
│ 干预选项 / 结果变化 / 结算摘要                │
│ [继续] [干预] [确定]                          │
└──────────────────────────────────────────────┘
```

---

## 4. 事件阶段

```text
进入事件
→ 显示事件标题与参与角色
→ 分段播放事件文本
→ 可选：玩家干预
→ 展示角色反应
→ 展示资源 / 缘线 / 业线变化
→ 点击确定返回主地图
```

## 5. 组件清单

| 组件 | 类型 | 内容 | 交互 |
|---|---|---|---|
| 事件标题 | `Label` | 事件名 | 无 |
| 参与角色 | 头像列表 | 角色头像、姓名 | 点击打开人物面板，关键演出中可禁用 |
| 事件文本 | `RichTextLabel` | 分段文本 | 点击推进 / Space 推进 |
| 演出区 | `TextureRect` / 图标 | 简单背景、表情、图标 | 无 |
| 干预区 | `Button` 列表 | 可用干预选项 | 点击进入干预确认 |
| 结算区 | 列表 | 资源、关系、业线变化 | 无 |
| Auto | `ToggleButton` | 自动播放 | 切换 Auto |
| 继续 | `Button` | 下一段文本 | 点击推进 |
| 确定 | `Button` | 结束事件 | 结算阶段可用 |

## 6. 文本推进规则

| 操作 | 结果 |
|---|---|
| 点击文本区 | 若正在逐字显示，则立即显示完整句；否则进入下一段 |
| 点击继续 | 同上 |
| Space | 同上 |
| Auto 开启 | 按设置的 Auto 速度自动推进 |
| Esc | 非关键事件退出；关键事件弹确认 |

---

## 7. 干预规则（v1.1）

干预不再是"事件开始前的一次性下拉列表"，而是与叙事节奏耦合的**关键节点赐福**（详见 §14）。

- 事件推进面板在遇到含 `blessing_prompt` 的段落时暂停并弹出赐福决策弹窗。
- 弹窗字段：干预名（默认"赐福"）、目的、难度文本、难度值、消耗、成功文案预告、失败文案预告。
- 神力不足时"赐福"按钮灰化，"跳过"按钮仍可用；跳过不扣神力。
- 一场事件可以有多个赐福节点，每个节点独立结算，不再有"整场事件只能干预一次"的限制。
- 已完成事件在回看模式下不再弹出赐福弹窗（§15）。

其它干预（托梦已移至人物面板，牵引机缘 / 遮蔽灾兆 / 显灵警示 / 强化观察均未实现）不再出现在事件推进面板中。

---

## 8. 结算展示

| 类型 | 表现 |
|---|---|
| 香火变化 | 香火 +3 / -2 |
| 神力变化 | 神力 -2 |
| 阳德 / 阴德 | 阳德 +5 / 阴德 +3 |
| 缘线变化 | 林潮音 ↔ 陈远舟 友情 +5 |
| 业线变化 | 林潮音主业线推进至 65% |
| 新线索 | 解锁“港口夜谈” |

结算以列表方式展示，不使用复杂动画。可配合小图标和数字跳动。

---

## 9. 后续跳转规则

事件结算完成后，点击“确定”按以下规则跳转：

1. 若事件结果直接触发 Game Over，进入 `ui-spec-game-over.md`。
2. 若当前由时间推进队列触发，且仍有待播放关键事件，进入下一条关键事件。
3. 若当前由时间推进队列触发，且所有关键事件已完成，返回 `ui-spec-time-advance.md` 的后续跳转判断。
4. 若玩家从主地图、地点面板或人物面板主动打开事件，返回来源界面；来源缺失时返回主地图 HUD。
5. 若事件解锁新线索，显示 Toast 或在结算列表中标记，不中断返回流程。

## 10. 状态与变体

| 状态 | 表现 |
|---|---|
| 普通事件 | 标准文本 + 结果 |
| 关键事件 | 退出需确认，标题有特殊标记 |
| 危险事件 | 红色边框 / 警告图标 |
| 已读事件 | 可快速跳过已读文本，若设置允许 |
| AI 文本失败 | 使用预设模板文本兜底 |
| 无可用赐福节点 | 事件推进面板不弹任何赐福弹窗，按普通流程推进 |
| 神力不足 | 赐福弹窗的"赐福"按钮灰化，"跳过"按钮仍可用 |
| **已完成事件**（v1.1） | 卡片边框变绿、整体降饱和、风险标签替换为"✓ 已完成"；再次进入切换为**回看模式** |

## 11. 关键节点赐福决策弹窗（v1.1）

事件推进面板在遇到含 `blessing_prompt` 的段落时暂停并弹出决策弹窗：

```text
┌──────────────────────────────────────────────┐
│ 赐福 · {事件名}                       [×]     │
├──────────────────────────────────────────────┤
│ 目的：{purpose}                              │
│ 难度：{difficulty_text}                      │
│ 消耗：{cost} 神力                             │
├──────────────────────────────────────────────┤
│ 成功文案：{success_effect}                   │
│ 失败文案：{failure_effect}                   │
├──────────────────────────────────────────────┤
│               [跳过]   [赐福 · 命运硬币 +1]  │
└──────────────────────────────────────────────┘
```

| 项目 | 规则 |
|---|---|
| 触发时机 | 段落级，逐段推进时遇 `blessing_prompt` 暂停 |
| 决策选项 | 「跳过」或「赐福」（赐福使命运硬币数 +1） |
| 神力不足 | 「赐福」按钮灰化并显示原因，「跳过」按钮仍可用 |
| 跳过 | 不扣神力，按 `failure_effect` 演出 |
| 赐福 | 扣神力，命运硬币判定后按结果播放 `success_effect` 或 `failure_effect` |
| 回看模式 | 不再弹窗，按已记录的分支自动播放对应文本 |

数据字段参见 `system/事件系统.md §4.2`。判定规则参见 `system/神力干预系统.md §7`。

## 12. 已完成事件的显示与回看（v1.1）

事件演出结束后**永久锁定**，玩家可回看但不可重演。

### 12.1 事件列表卡片（事件 Tab）

| 状态 | 表现 |
|---|---|
| 未完成 | 默认风格：边框随风险色，标签显示风险等级，点击打开事件推进面板（可赐福） |
| 已完成 | 边框变为绿色系（约 `#8cb697`）、整体降饱和（modulate ≈ 0.8）、风险标签替换为"✓ 已完成"，Tooltip 追加"· 演出已定" |

### 12.2 事件详情弹窗

| 项目 | 未完成 | 已完成 |
|---|---|---|
| 主按钮文案 | 「进入事件」 | 「回看事件」 |
| 主按钮行为 | 进入可干预的事件推进面板 | 进入回看模式的事件推进面板 |
| 结果小节 | 隐藏 | 显示 `CompletedSnapshot.outcome_summary` 与赐福节点历史 |
| 赐福按钮 | 进入后可能触发赐福弹窗 | 进入后不触发任何赐福弹窗 |

### 12.3 回看模式的视觉反馈

- 顶栏在事件名旁追加小标「回看」。
- 文本推进规则与正常模式一致（Space / 点击推进 / Auto）。
- 已选分支按 `CompletedSnapshot.blessing_results` 自动播放（赐福成功的段落按 `success_effect` 播出；失败或跳过的段落按 `failure_effect` 播出）。
- 回看结束返回来源界面。

## 13. Godot 实现建议

```text
EventPanel (PanelContainer)
├── Header (HBoxContainer)
│   ├── EventTitleLabel
│   ├── ReviewBadge (Label, v1.1 回看模式小标)
│   └── AutoToggle
├── Content (HBoxContainer)
│   ├── CharacterList (VBoxContainer)
│   └── TextAndStage (VBoxContainer)
│       ├── StageImage (TextureRect)
│       └── EventText (RichTextLabel)
├── ResultOrChoiceArea (VBoxContainer)
├── CompletedSummary (RichTextLabel, v1.1 回看模式显示)
└── FooterButtons (HBoxContainer)
    ├── ContinueButton
    └── ConfirmButton
```

`InterveneButton` 在 v1.1 中移除，赐福入口已下沉到叙事段落级（见 §11）。

## 14. 数据需求

| 数据 | 来源 | 用途 |
|---|---|---|
| 事件基础信息 | EventDatabase | 标题、地点、参与角色 |
| DialogueSegments | EventNarrativeSystem | 分段脚本与 `blessing_prompt` |
| 参与角色 | NPCDatabase | 头像、姓名 |
| 神力值 | PlayerResourceSystem | 控制赐福按钮灰化 |
| 结算结果 | EventResolutionSystem | 资源、关系、业线变化 |
| 已读状态 | EventHistorySystem | 控制跳过已读 |
| IsCompleted / CompletedSnapshot（v1.1） | StateService | 控制卡片外观、详情弹窗主按钮、回看模式分支 |

## 15. 验收标准

- [ ] 点击事件标记后能打开事件推进面板。
- [ ] 事件标题、参与角色和第一段文本显示正确。
- [ ] 点击文本区、继续按钮或 Space 能推进文本。
- [ ] Auto 开关能自动推进文本，并受设置中的 Auto 速度影响。
- [ ] 遇到 `blessing_prompt` 段落时暂停并弹出决策弹窗，展示目的、难度、消耗、成功/失败文案预告。
- [ ] 神力不足时"赐福"按钮灰化并显示原因；"跳过"按钮仍可用。
- [ ] 执行赐福后扣神力、命运硬币数 +1、判定按规则分支播出对应文本。
- [ ] 同一事件多个赐福节点各自独立决策与结算。
- [ ] 事件演出结束后 `IsCompleted = true`，事件列表卡片切换为"✓ 已完成"外观。
- [ ] 再次打开已完成事件时进入回看模式，不再弹赐福弹窗、不消耗神力、按已记录分支播放。
- [ ] 事件结束后展示资源、缘线或业线变化。
- [ ] 点击确定后返回主地图并刷新相关状态。
- [ ] AI 文本失败时能显示预设兜底文本。
